# Community Mental Health Peer-Support Network
# Chatbot Knowledge Base

## 1. Platform Purpose

The Community Mental Health Peer-Support Network is a community-based peer-support application.

The platform helps users:

- Find suitable peer-support groups.
- Request to join support groups.
- Communicate with approved group members.
- Share experiences.
- Comment and reply to discussions.
- React to posts.
- Report harmful or inappropriate content.
- Access community support features.

The platform provides peer support.

It is not a replacement for a doctor, psychologist, psychiatrist, counsellor, therapist, hospital, emergency service, or other qualified healthcare professional.

---

## 2. User Roles

The application has four main registered user roles:

- USER
- PEER_SUPPORTER
- MODERATOR
- ADMIN

Unregistered visitors may use public features such as the chatbot when available, but protected application features require an account.

---

## 3. Normal User

A normal USER can:

- Register an account.
- Verify the email address using an OTP.
- Login.
- Manage profile information.
- Add, change, or remove a profile picture.
- Change the account password.
- Reset a forgotten password.
- Browse available support groups.
- Request to join a support group.
- View joined groups.
- Access a private group after membership approval.
- Create posts where permitted.
- Comment on posts.
- Reply to comments.
- React to content.
- Report harmful or inappropriate content.
- Logout.
- Logout from all devices.

A normal User cannot approve group join requests.

A normal User cannot perform Moderator actions.

A normal User cannot perform Administrator actions.

---

## 4. Peer Supporter

A PEER_SUPPORTER is assigned to specific support groups by an Administrator.

A Peer Supporter does not freely select any group to manage.

A Peer Supporter can work with groups assigned by the Administrator.

A Peer Supporter can:

- View assigned groups.
- View group discussions.
- Review pending join requests for assigned groups.
- Approve suitable join requests.
- Reject unsuitable join requests.
- Welcome group members.
- Give general peer support.
- Guide positive discussions.
- Share useful resources.
- Help members understand group rules.
- Escalate safety concerns when necessary.

A Peer Supporter is not a professional therapist and should not diagnose mental-health conditions or prescribe treatment.

---

## 5. Moderator

A MODERATOR is assigned to specific support groups by an Administrator.

A Moderator can:

- View assigned groups.
- Monitor group discussions.
- Review reports.
- Review reported posts.
- Review reported comments.
- Review relevant user information.
- Warn users when appropriate.
- Remove harmful content.
- Suspend a member from a group when allowed.
- Reactivate a suspended group member when allowed.
- Remove a member from a group when allowed.
- Add moderation notes.
- Escalate serious situations to an Administrator.
- View moderation history.

The Moderator normally moderates only groups assigned by the Administrator.

---

## 6. Administrator

An ADMIN manages platform-level access and administration.

An Administrator can:

- View users.
- Search users.
- Filter users.
- View user details.
- Change user roles.
- Change account status.
- Suspend accounts.
- Reactivate accounts.
- Deactivate accounts.
- Revoke user sessions.
- Create and manage support groups.
- Assign Peer Supporters to groups.
- Assign Moderators to groups.
- Remove or change group assignments.
- Review serious escalations.

Daily group support is mainly handled by Peer Supporters.

Daily moderation is mainly handled by Moderators.

---

## 7. Registration

To create an account:

1. Open the registration screen.
2. Enter the required account information.
3. Provide a valid email address.
4. Create a password.
5. Submit the registration form.
6. The system sends an OTP to the registered email address.
7. Enter the OTP to verify the email.
8. After successful verification, the account can be used to login.

New normal accounts use the USER role by default unless an Administrator later changes the role.

---

## 8. Email Verification

The application uses email OTP verification.

After registration:

1. An OTP is sent to the registered email.
2. The user enters the OTP.
3. The system validates the OTP.
4. The email becomes verified after successful validation.

If necessary, the user can request another verification OTP according to system limits.

---

## 9. Login

Registered and verified users can login using their supported authentication method.

After successful login, the application uses the user's role and permissions to provide the correct application experience.

---

## 10. Forgot Password

If a user forgets the password:

1. Open Forgot Password.
2. Enter the registered email address.
3. Request a password-reset OTP.
4. Check the email.
5. Enter the OTP.
6. Enter a new password.
7. Submit the reset request.
8. Login using the new password.

The OTP is temporary and may expire.

---

## 11. Change Password

A logged-in user who has a local password can use the Change Password feature.

The user normally provides:

- Current password.
- New password.

After a successful password change, existing sessions may be revoked for account security.

---

## 12. Profile

A logged-in user can manage profile information.

Available profile functions may include:

- View profile.
- Update name or supported profile details.
- View email.
- View role.
- View account status.
- Change password.
- Manage profile picture.
- Logout.
- Logout from all devices.

---

## 13. Profile Picture

A logged-in user can:

- Add a profile picture.
- Change an existing profile picture.
- Remove the current profile picture.

If the user has no profile picture, the application can display a default avatar or the user's initials.

---

## 14. Support Groups

Support groups are private peer-support communities.

A group may have:

- Group name.
- Topic or category.
- Description.
- Rules.
- Eligibility information.
- Peer Supporters.
- Moderators.
- Approved members.

Private group discussions should only be visible to authorized users.

---

## 15. How to Join a Support Group

The normal process is:

1. Login to the application.
2. Open the Groups area.
3. Browse available support groups.
4. Select a suitable group.
5. Read the group description and rules.
6. Select Request to Join.
7. Enter a reason for joining.
8. Submit the request.
9. The request becomes Pending.
10. A Peer Supporter assigned to that group reviews the request.
11. The Peer Supporter approves or rejects the request.
12. If approved, the user becomes an active group member.
13. The user can then access the private group feed.

An unregistered visitor must create and verify an account before joining a private support group.

---

## 16. Join Request Status

A join request may have statuses such as:

- PENDING
- APPROVED
- REJECTED

PENDING means the request is waiting for review.

APPROVED means the user has been accepted into the group.

REJECTED means the request was not approved.

---

## 17. Group Membership

After a join request is approved, the User becomes a member of that group.

A membership may be:

- ACTIVE
- SUSPENDED
- REMOVED

An ACTIVE member can participate according to group permissions.

A SUSPENDED or REMOVED member may lose access to some or all group functions.

---

## 18. Group Feed

The private group feed is available to authorized users.

This normally includes:

- Approved members.
- Assigned Peer Supporters.
- Assigned Moderators.
- Authorized Administrators.

Inside a group feed, permitted users can:

- Read posts.
- Create posts.
- Comment.
- Reply.
- React.
- Report inappropriate content.

Normal posts can be displayed with newer posts first.

Important resource posts may be pinned.

---

## 19. Posts

Authorized group members can create posts according to group rules.

Posts may contain peer-support discussions, experiences, questions, or useful information.

Users should avoid sharing unnecessary sensitive personal information publicly.

---

## 20. Comments and Replies

Users with appropriate access can comment on group posts.

Users can also reply to comments where supported.

Comments and replies should follow community rules.

Harmful or inappropriate comments can be reported.

---

## 21. Reactions

Users may react to posts or supported content.

Reactions are intended to provide simple engagement and supportive feedback.

---

## 22. Reporting Content

If a user sees harmful, abusive, unsafe, spam, or rule-breaking content:

1. Select the Report option.
2. Select or enter a report reason.
3. Submit the report.
4. The report is sent privately for moderation.
5. An authorized Moderator reviews the report.

The reporting user's identity should not be publicly shown to other group members.

---

## 23. Moderator Actions

After reviewing a report, a Moderator may take an appropriate action according to system rules.

Possible actions can include:

- No Action.
- Warning.
- Remove harmful content.
- Suspend a member from a group.
- Reactivate a group member.
- Remove a member from a group.
- Escalate the situation to an Administrator.

Moderation actions may be stored in moderation history.

---

## 24. Account Status

Account statuses include:

- ACTIVE
- SUSPENDED
- DEACTIVATED

An ACTIVE account can access features according to its role.

A SUSPENDED or DEACTIVATED account may be prevented from using protected application features.

---

## 25. Logout

Logout ends the current application session.

Logout All Devices is intended to revoke all active sessions for the user's account.

---

## 26. Privacy

Users should avoid sharing unnecessary sensitive personal information.

Private group content should only be available to authorized users.

Reports should be handled privately.

Administrative and moderation information should only be visible to authorized users.

---

## 27. What an Unregistered Visitor Can Do

An unregistered visitor can use public features that the application makes available, including this chatbot.

An unregistered visitor cannot automatically:

- Join a private support group.
- Access a private group feed.
- Create private group posts.
- Comment inside private groups.
- Perform moderation actions.
- Perform administrative actions.

The visitor should register and verify an account before using protected community features.

## 29. Chatbot Limitations

The chatbot must not invent application features.

The chatbot must not claim that it performed an application action.

For example, it must not claim:

- "I approved your group request."
- "I changed your password."
- "I suspended that user."
- "I deleted the post."

The chatbot only provides information and guidance.

If information about an application feature is not available in this knowledge base, respond:

"I don't have enough information about that feature. Please contact an administrator or support person."

---

## 30. Medical and Mental-Health Limitations

The chatbot is not a medical professional.

The chatbot must not:

- Diagnose mental-health conditions.
- Prescribe medication.
- Recommend medication dosage.
- Tell a user to start medication.
- Tell a user to stop medication.
- Tell a user to change medication dosage.
- Pretend to be a doctor.
- Pretend to be a therapist.
- Pretend to be a psychologist.
- Pretend to be a psychiatrist.
- Pretend to be a counsellor.

For professional medical or mental-health advice, the user should contact an appropriately qualified healthcare professional.

---

## 31. Urgent Safety Situations

If a user indicates that they may harm themselves, end their life, harm another person, or are in immediate danger, the chatbot should treat the situation as urgent.

The chatbot should encourage the person to:

- Seek immediate human help.
- Contact local emergency services or an available crisis service.
- Contact a trusted person who can stay with them.
- Move to a safer place when possible.

The chatbot must clearly state that it is not an emergency or medical service.
